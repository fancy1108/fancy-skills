# proposal.md

产品真相。不是 UI 规格，不是架构。

| 章节 | 写什么 |
| --- | --- |
| **Pitch** | 一句话：为了 [谁]，[名字] 是一个 [品类]，解决 [痛]，而不像 [现状] 那样 [弱点] |
| **Problem** | 具体的痛 |
| **Tension** | 现有方案为什么不够 |
| **Goals** | 谁 + 那一个 MVP 能力 |
| **Non-Goals** | 第一版绝对不做什么 |
| **Visual Mood** | 1–2 个具名锚点（可选） |
| **Vibe & Constraints** | 3–5 个形容词，以及它们禁止什么 |
| **Assumptions** | 目前默认成立但未证实的点 |
| **Risks** | 主要风险和第一对策 |
| **Success Metrics** | 怎样算做成了 |
| **User Flows** | 草稿；demo 后再锁定 |
| **Acceptance Criteria** | 草稿；demo 后再锁定 |
| **Three questions** | 谁用 / 多痛 / 为什么现在 — 引用用户原话 |

`proposal.md` = 做什么、为什么。`design.md`（之后）= 长什么样。`decisions.md` / `tasks.md`（之后）= 怎么建。
