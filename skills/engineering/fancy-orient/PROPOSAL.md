# proposal.md

Product truth. Not a UI spec, not an architecture.

| Section | What belongs here |
| --- | --- |
| **Pitch** | One sentence: for [who], [name] is a [category] that solves [pain], unlike [status quo] which [weakness] |
| **Problem** | The concrete pain |
| **Tension** | Why current options fail |
| **Goals** | Who + the one MVP capability |
| **Non-Goals** | What v1 will not do |
| **Visual Mood** | 1–2 named anchors (optional) |
| **Vibe & Constraints** | 3–5 adjectives and what they forbid |
| **Assumptions** | Defaults not yet proven |
| **Risks** | Main risks and a first counter |
| **Success Metrics** | How we would know it worked |
| **User Flows** | Draft; lock after a demo |
| **Acceptance Criteria** | Draft; lock after a demo |
| **Three questions** | Who / how painful / why now — quoted from the user |

`proposal.md` = what and why. `design.md` (later) = design spec (tokens). `visual.md` (later) = screens and bans. `decisions.md` / `tasks.md` (later) = how it is built.

The written file is a draft until the user says it is right.
