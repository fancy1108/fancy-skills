# 视觉（第 4 步）

仅 UI 产品。无 UI → 跳过本文件；在 `decisions.md` 写无 UI 豁免。已有可跑原型（第 5.5 步）→ 跳过本文件；从那份 UI 反提 `design.md`。

**不要先写 `design.md`。不要先写 `demo.html`。** 在对话里诊疗、锁定，再做 demo。

## 1. 三个方向 — 停这一轮

根据提案里的一句话 Pitch（不要只凭一个 vibe 形容词），在**对话里**给出 **三个**带标签的方向。每一行：

- **名称**
- **1–2 个具名参照**（真实产品，不是「极简」「现代」）
- **色温** `oklch()`（一个背景 + 一个强调色就够）
- **字体搭配**
- **禁止什么**

做成 A / B / C（或一张表）。可以标一个推荐。然后 **停这一轮。** 等他们选或混搭。

一个 vibe 形容词不算选定。提案里的 **Visual Mood** 不算选定。你自己说「那就走冷静/干净风」不算选定。

这一轮禁止：`design.md`、`demo.html`、用效果图代替选择、任何其他 UI 文件。

之后可以收回（「换视觉」）。再给三个方向。demo 变回草稿。

## 2. `design.md`

只有他们选了（或混了）才写。写短。必须有：

- 选定的参照
- 颜色 token（`oklch()` — 契约里不要 hex）
- 字体 + 间距尺度
- 本产品**实际有的**屏幕地图（不要发明多余页面）
- 至少 **五条视觉禁令**（卡片病、灰汤、彩虹渐变、死掉的空状态，…）

写完文件，在对话里复述选定的参照 + token，**停这一轮。** 这一轮不要写 `demo.html`。

## 3. 锁死

把 3–5 条视觉铁律追加进 `CLAUDE.md`（祈使句：改 UI 前先读 `design.md`；禁止 hex；新 token 必须先改 `design.md`）。

## 4. 快审

`design.md` 写好后对照禁令检查。违规则先改文件再做 demo。不要发明本集合没有的审核 Agent。
